# MiniMax Code Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** 为现有单文件 Worker 增加 MiniMax Code 国内版设备授权、自动续期和每日签到，部署无需新增绑定。

**Architecture:** 新建独立 IIFE 平台模块，通过 minimax: KV 视图保存加密记录，外壳负责路由和跨平台运行。前端由 Antigravity 在独立临时片段文件中实现，由主 Agent 整合入 PAGE。

**Tech Stack:** 原生 JavaScript、Cloudflare Workers fetch/Web Crypto、Workers KV、Node 内置 node:test（仅开发验证）。

---

### Task 1：先建立可复现的协议测试
**Files:** Create `tests/minimax.test.mjs`; Modify `worker.js`。
- [x] 用 node:vm 加载 worker.js 并替换 export default 为可访问的模块，注入内存 KV、fetch 和 Web Crypto；MD5 适配仅在 Node 测试注入。
- [x] 写公开请求测试：`POST /minimax/api/login/start` 必须鉴权；OAuth 返回设备信息后响应公开 nonce，不得暴露 verifier/device_code；KV 不含明文令牌。
- [x] 写授权轮询测试：pending/slow_down/过期/成功并去重；成功获得真实 user ID 后存储账号。
- [x] 写签到测试：七日面板、status=3 已签、status=2 可领、claim_result=1 计入累计、claim_result=2 不累计、缺失回执不报成功、续期令牌在身份查询前保存。
- [x] 运行 `node --test tests/minimax.test.mjs`，确认新增路由缺失导致失败。

### Task 2：实现独立平台模块
**Files:** Modify `worker.js`（PAGE 之外）。
- [x] 使用 `crypto.subtle.digest('MD5', ...)` 复刻签名，SHA-256 实现 PKCE；请求设置 20 秒超时，所有异常返回静态安全说明与数字错误码，不回显凭据。
- [x] 用 `nvSeal`/`nvOpen` 包装加密记录，账号索引只存 ID；账号 ID 为 realUserID 的 SHA-256 前 24 个十六进制字符。
- [x] 实现设备授权 start/poll，限制官方授权 URL、限制会话时效、保存轮询节流与 slow_down；令牌校验 scope/type/expires；不输出令牌。
- [x] 实现 get/list/rename/remove/run，严格校验面板和领取回执；仅今日已签可标记 lastOkDate，记录本次和本工具累计。
- [x] 集成 minimaxEnv、路由、runAll、formatReport；scheduled 统一调用 runAll 保证发送汇总通知。
- [x] 运行协议测试并修正失败项。
